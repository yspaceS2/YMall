# 이메일 인증과 변경

YMall은 일반·소셜 회원가입과 로그인 이메일 변경에서 이메일 소유권을 검증합니다.

## 일반 회원가입

1. 이메일 중복 여부를 확인합니다.
2. 인증번호를 발송하고 Redis에 인증번호의 SHA-256 digest만 5분간 저장합니다.
3. 인증번호 확인에 성공하면 이메일 digest와 연결된 일회성 인증 완료 토큰을 10분간 발급합니다.
4. 회원가입 요청은 이메일과 인증 완료 토큰을 함께 전송합니다.
5. 서버는 토큰이 해당 이메일에 발급됐는지 원자적으로 확인하고 토큰을 즉시 소모합니다.
6. 최종 회원 생성 트랜잭션에서 이메일 중복을 다시 확인합니다.
7. 가입이 완료되면 `members.email_verified_at`에 인증 완료 시각을 저장합니다.

인증번호 발송은 이메일을 선점하지 않습니다. 토큰은 다른 이메일에 사용할 수 없고 한 번 사용하면
다시 사용할 수 없습니다.

## 재인증 방식

- 비밀번호가 있는 회원은 현재 비밀번호를 확인합니다.
- 비밀번호가 없는 소셜 전용 회원은 현재 등록 이메일로 받은 인증번호를 확인합니다.
- 재인증 결과는 Redis에 10분 동안만 유지하며 현재 회원 이메일의 digest와 연결합니다.
- 재인증 이후 회원 이메일이 달라지면 기존 재인증 결과를 사용할 수 없습니다.

## 새 이메일 인증과 동시성

1. 인증번호 발송 전에 이메일 중복 여부를 확인합니다.
2. 이메일을 인증번호 발송 시점에 예약하거나 선점하지 않습니다.
3. 인증번호는 Redis에 평문으로 저장하지 않고 SHA-256 digest로 저장합니다.
4. 인증번호 확인은 Lua script로 시도 횟수 증가와 일회성 소비를 원자적으로 처리합니다.
5. 최종 변경 트랜잭션에서 이메일 중복을 다시 확인합니다.
6. `members.email`의 `UNIQUE` 제약조건을 최종 동시성 방어선으로 사용합니다.
7. 같은 이메일을 동시에 변경하려는 경우 먼저 커밋한 요청만 성공하며 나머지는 `409 Conflict`를 받습니다.

## 변경 완료 후 처리

- `members.email`과 `members.email_verified_at`을 변경합니다.
- `oauth_accounts`의 provider 및 provider ID 연결은 변경하지 않습니다.
- 해당 회원의 모든 Refresh Token을 Redis에서 폐기합니다.
- 브라우저의 Refresh Token cookie와 이메일 변경 세션을 제거합니다.
- 프런트에 저장된 Access Token을 제거하고 새 이메일로 다시 로그인하도록 안내합니다.
- 기존 이메일로 변경 완료 보안 알림을 발송합니다.

Access Token은 짧은 만료 시간을 사용하며 서버 로그에는 이메일, 인증번호, 토큰을 기록하지 않습니다.

## 보안 감사 로그

성공한 변경은 회원 ID만 `info` 수준으로 기록합니다. 이메일 변경 알림 발송 실패는 회원 ID와 함께 `warn`
수준으로 기록하되 기존·신규 이메일, 인증번호, 토큰은 로그에 포함하지 않습니다.

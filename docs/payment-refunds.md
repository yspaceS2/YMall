# 결제 취소·환불 운영 가이드

## 처리 범위

YMall의 결제 후 환불은 Toss Payments 취소 API를 호출한 뒤 검증된 결제사 응답을 기준으로 주문, 결제, 재고와 환불 이력을 함께 갱신한다.

- 전체 환불: 환불 가능한 잔여 주문 항목 전체를 취소한다.
- 부분 환불: 주문 항목과 수량을 지정해 취소한다.
- 배송 준비가 시작되지 않은 `PENDING` 주문 항목만 환불할 수 있다.
- 주문 상태가 `PAID` 또는 `PARTIALLY_REFUNDED`일 때만 새 환불을 요청할 수 있다.
- 성공한 환불 금액 합계는 원결제 금액을 초과할 수 없다.

## 권한

| 역할 | 요청 경로 | 처리 범위 |
| --- | --- | --- |
| 사용자 | `POST /api/orders/{orderId}/refunds` | 본인 주문 |
| 판매자 | `POST /api/seller/orders/{orderId}/refunds` | 본인 판매 상품 |
| 관리자 | `POST /api/admin/orders/{orderId}/refunds` | 모든 주문 |

각 역할의 조회 API는 같은 경로에 `GET`을 사용한다. 판매자 조회에는 다른 판매자의 환불 항목이 포함되지 않는다.

## 요청 예시

```json
{
  "idempotencyKey": "refund-request-unique-key",
  "reason": "단순 변심",
  "items": [
    {
      "orderItemId": 10,
      "quantity": 1
    }
  ]
}
```

`items`를 생략하면 해당 요청자가 환불할 수 있는 잔여 수량 전체를 대상으로 한다. 동일 주문에서 같은 `idempotencyKey`를 다시 보내면 결제사 취소 API를 재호출하지 않고 기존 환불 결과를 반환한다.

## 처리 상태

| 상태 | 의미 | 후속 조치 |
| --- | --- | --- |
| `PENDING` | 결제사 취소 요청 처리 중 | 추가 환불 차단 |
| `SUCCEEDED` | 결제사 응답 검증과 내부 반영 완료 | 별도 조치 없음 |
| `FAILED` | 결제사가 요청을 거절했거나 검증 전에 실패 | 원인 확인 후 새 멱등 키로 재요청 가능 |
| `UNKNOWN` | 타임아웃·연결 장애로 결제사 처리 결과를 확정할 수 없음 | 결제사 상태 조회 후 정합성 확인 필요 |

주문 하나에는 동시에 하나의 미완료 환불만 허용한다. `PENDING` 또는 `UNKNOWN` 이력이 있으면 새 환불 요청은 `PAYMENT_REFUND_RECONCILIATION_REQUIRED`로 차단된다.

## 정합성 규칙

1. 주문 행을 잠근 뒤 멱등 키와 기존 미완료 환불을 확인한다.
2. 환불 가능 수량과 잔여 결제 금액을 서버 데이터로 다시 계산한다.
3. `PENDING` 이력을 커밋한 다음 DB 트랜잭션 밖에서 결제사 API를 호출한다.
4. 결제 키, 주문번호, 원결제 금액, 결제사 잔액과 취소 상태를 검증한다.
5. 성공한 수량만 재고에 더하고 `refundedQuantity`에 기록한다.
6. 잔액이 남으면 주문을 `PARTIALLY_REFUNDED`, 잔액이 0이면 `REFUNDED`로 변경한다.

부분 환불 이후 외부 전체 취소 웹훅이 도착하면 이미 환불된 수량을 제외한 나머지 수량만 복구한다. 내부 환불 요청이 처리 중이면 웹훅은 재고를 직접 변경하지 않고 동기 환불 완료 처리를 기다린다.

## 실패 및 미확정 상태 확인

1. 환불 조회 API에서 `failureMessage`와 상태를 확인한다.
2. `FAILED`이면 입력 오류나 결제사 거절 원인을 수정하고 새 멱등 키로 재요청한다.
3. `UNKNOWN`이면 Toss Payments 결제 조회 API 또는 관리자 콘솔에서 실제 `balanceAmount`와 취소 상태를 먼저 확인한다.
4. 내부 환불 합계와 결제사 잔액이 일치하는지 확인하기 전에는 새 환불을 실행하지 않는다.
5. 불일치가 확인되면 이력을 삭제하거나 임의 수정하지 말고 정합성 보정 작업으로 처리한다.

API 키, 결제 키 전체 값, 사용자 개인정보는 로그·문서·Jira·PR에 기록하지 않는다.

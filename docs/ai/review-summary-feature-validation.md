# AI 리뷰 요약 기능 검증

## 사용자 노출 기준

상품 상세 화면은 AI 요약과 사용자가 작성한 원본 리뷰를 명확히 구분한다.

| 상태 | 화면 동작 |
| --- | --- |
| 조회 중 | AI 리뷰 요약 상태를 확인 중이라는 안내를 표시한다. |
| 생성 조건 미충족 | 현재 리뷰 수와 함께 리뷰가 더 쌓이면 요약이 제공된다고 안내한다. |
| 생성 완료 | 장점, 단점, 공통 의견, 요약 대상 리뷰 수와 생성 시각을 표시한다. |
| 최초 조회 실패 | 요약을 불러오지 못했다는 안내와 재시도 버튼을 표시한다. |
| 갱신 실패 | 마지막으로 조회한 기존 요약을 유지하고 최신 상태 확인 실패를 알린다. |

AI 요약 API는 원본 리뷰 API와 독립적으로 호출한다. 따라서 모델, Kafka, Redis 또는
요약 API에 문제가 생겨도 원본 리뷰 조회와 페이지의 구매 기능은 계속 사용할 수 있다.
화면에는 AI 결과가 참고용이며 원본 리뷰의 일부 맥락이나 소수 의견을 놓칠 수 있다는
안내를 함께 표시한다.

## 대표 입력과 출력

아래 예시는 저장소의 합성 키보드 리뷰 표본과 기준 모델 평가 결과에서 가져왔다.
실제 개인정보나 외부 서비스 리뷰는 사용하지 않았다.

입력의 주요 의견:

- 타건 소음이 작고 장시간 문서 작업에도 편안함
- 블루투스 연결과 기기 전환이 빠름
- 어두운 곳에서 키 각인이 잘 보이지 않음
- 배터리가 오래가고 크기가 적당함

Qwen3-0.6B-GGUF Q8_0의 평가 출력:

```json
{
    "pros": [
        "키를 누르면 소리가 조용하고, 문서 작업을 해도 손가락이 편안합니다."
    ],
    "cons": [
        "블루투스 연결이 빠르지만, 어두운 곳에서는 키 각인이 잘 보이지 않아 아쉽습니다."
    ],
    "commonOpinions": [
        "배터리가 오래, 크기가 적당한 만족스러운 요소입니다."
    ]
}
```

출력은 필수 JSON 구조를 지켰지만, 장점인 빠른 블루투스 연결을 단점 문장에 섞었다.
또한 한 리뷰의 배터리·크기 의견을 공통 의견으로 표현했다. 이 사례는 형식 검증 통과가
내용의 정확성을 보장하지 않는다는 점을 보여 준다.

## 품질 평가 결과

2026-07-24에 합성 상품 6개를 대상으로 로컬 CPU 환경에서 비교했다.

| 항목 | 결과 |
| --- | --- |
| 기준 모델 | `Qwen/Qwen3-0.6B-GGUF` Q8_0 |
| 복구 가능한 JSON | 100% |
| 필수 스키마 준수 | 100% |
| 섹션 완성률 | 100% |
| 평균 ROUGE-L | 0.1496 |
| 생성 지연 | p50 2.7212초, p95 2.7343초 |
| 양자화 모델 파일 | 약 604.15 MiB |

`google/mt5-small`은 현재 프롬프트에서 요약을 생성하지 못해 제외했다. LoRA 실험은
형식 준수는 개선했지만 환각, 감성 왜곡, 소수 의견 과대표현이 남아 서비스 모델로
채택하지 않았다. 현재 서비스는 기준 Qwen 모델과 방어적 프롬프트·응답 파서를 사용한다.

## 알려진 한계

- 평가는 합성 상품 6개만 사용했으며 실제 운영 분포를 대표하지 않는다.
- 독립 평가자의 블라인드 사람 평가와 BERTScore를 아직 수행하지 않았다.
- 한 리뷰에만 있는 의견을 공통 의견으로 과대표현할 수 있다.
- 장점과 단점이 한 문장에 섞이거나 감성이 반대로 분류될 수 있다.
- 입력 제한 때문에 리뷰가 매우 많으면 최신 리뷰 일부만 요약 대상이 된다.
- Kafka 비동기 생성이 완료되기 전까지 이전 요약 또는 미생성 상태가 보일 수 있다.
- 모델 출력은 구매 판단을 대신하지 않으며 원본 리뷰 확인이 필요하다.

운영 품질을 주장하려면 상품군별 승인 데이터 확대, 독립 사람 평가, 근거 일치율과
공통 의견 정밀도 측정, 입력 길이별 지연·메모리 부하 검증이 추가로 필요하다.

## 라이선스와 실행 구성

- 기준 모델: `Qwen/Qwen3-0.6B-GGUF` Q8_0
- 모델 라이선스: Apache-2.0
- 실행 엔진: Docker Model Runner의 llama.cpp CPU 엔진
- 데이터: 저장소에서 직접 작성한 합성 데이터. 외부 원문은 출처와 이용 조건을
  확인하기 전 학습·평가 데이터에 포함하지 않는다.
- 모델 파일: Docker 모델 캐시에 저장하며 Git 저장소와 애플리케이션 이미지에는
  포함하지 않는다.

최초 준비:

```powershell
docker desktop enable model-runner --tcp=12434
docker model pull hf.co/Qwen/Qwen3-0.6B-GGUF:Q8_0
```

추론 계약 검증:

```powershell
docker compose --profile ai-check run --rm ai-contract-check
```

## 변경 검증

프런트 변경 시 다음 검증을 수행한다.

```powershell
cd frontend
npm run lint
npm run build
```

화면 검증에서는 데스크톱과 모바일 너비에서 네 가지 상태를 확인하고, 키보드로
재시도 버튼에 접근할 수 있는지, 상태 안내가 스크린 리더에 전달되는지, AI 요청 실패
후에도 원본 리뷰가 표시되는지 확인한다.

# 리뷰 요약 모델 미세조정 및 평가

## 목적

YMALL-70은 오픈소스 리뷰 요약 모델을 바로 교체하는 작업이 아니라, 제한된
로컬 자원에서 미세조정과 평가를 재현하고 결과가 기준 모델보다 나을 때만
채택할 수 있는 절차를 만드는 실험이다.

## 실험 구성

| 항목 | 값 |
| --- | --- |
| 기준 모델 | `Qwen/Qwen3-0.6B` |
| 모델 리비전 | `c1899de289a04d12100db370d81485cdf75e47ca` |
| 라이선스 | Apache-2.0 |
| 학습 방식 | LoRA, `all-linear`, rank 8, alpha 16, dropout 0.05 |
| 프롬프트 버전 | 2.0 |
| 시드 | 20260724 |
| 데이터 | `synthetic-v1`, train 4 / validation 1 / test 1 |
| 학습 | 10 epochs, learning rate 0.0002, FP16 |
| 장비 | NVIDIA GeForce RTX 2080 SUPER 8GB |

전체 파라미터 약 6.01억 개 중 약 505만 개(0.84%)만 학습했다. 학습 설정은
[`ai/training/configs/qwen3-0.6b-lora-v1.json`](../../ai/training/configs/qwen3-0.6b-lora-v1.json),
학습 결과와 환경 정보는
[`ai/training/results/qwen3-0.6b-lora-v1-training.json`](../../ai/training/results/qwen3-0.6b-lora-v1-training.json)에
남긴다. 로컬 어댑터 파일은 해시로 식별하며 Git에는 커밋하지 않는다.

상품 그룹 단위로 train, validation, test를 분리해 동일 상품 리뷰가 서로 다른
분할에 섞이지 않도록 했다. 프롬프트에는 리뷰 내부 명령 무시, 긍정·부정 분리,
둘 이상의 리뷰가 뒷받침할 때만 공통 의견으로 기록하는 규칙을 포함했다.

## 기준 모델 대비 테스트

동일한 FP16 기준 모델, 프롬프트 2.0, 비샘플링 생성 조건에서 어댑터만
비활성화·활성화해 테스트 분할을 비교했다. CUDA 초기화 비용이 한 후보에만
포함되지 않도록 기준 모델과 LoRA 모델을 각각 짧게 워밍업한 뒤 측정했다.

| 지표 | 기준 모델 | LoRA |
| --- | ---: | ---: |
| 엄격 JSON 객체 | 0% | 100% |
| 복구 가능한 JSON | 100% | 100% |
| 스키마 유효 | 100% | 100% |
| 섹션 완전성 | 100% | 100% |
| ROUGE-L | 0.0896 | 0.0952 |
| 응답 시간 | 49.26초 | 50.19초 |

원본 결과 전체와 아티팩트 해시는
[`ai/training/results/qwen3-0.6b-lora-v1-evaluation.json`](../../ai/training/results/qwen3-0.6b-lora-v1-evaluation.json)에

테스트 샘플은 1개뿐이므로 백분율과 속도 차이는 통계적으로 유의하지 않다.
특히 속도는 워밍업, 시스템 부하, 생성 토큰 수에 영향을 받으므로 성능 향상으로
주장하지 않는다.

## 정성 평가

기준 모델은 JSON 코드 블록을 사용해 엄격 JSON 조건을 어겼고, 한 리뷰에만
있는 의견을 공통 의견으로 분류했다. LoRA 모델은 코드 블록 없이 JSON을
출력했지만 다음 품질 문제가 확인됐다.

- 원문은 “눈부시지 않다”고 했지만 단점에 눈부심이 있는 것처럼 표현해 감성을
  반대로 왜곡했다.
- 원문에 없는 “펌웨이”라는 무의미한 표현을 생성했다.
- 둘 이상의 리뷰가 직접 뒷받침하지 않는 내용을 공통 의견으로 일반화했다.
- 소수 의견인 받침대 흔들림을 실제 근거보다 장황하고 강하게 표현했다.

## 채택 결정

이번 LoRA 어댑터는 서비스 모델로 채택하지 않는다. 형식 준수는 개선됐지만
환각, 감성 왜곡, 소수 의견 과대표현이 남아 있어 사용자에게 노출할 품질 기준을
충족하지 못했다. YMall은 기존 Qwen3 기준 모델과 방어적 프롬프트·파서를
유지한다.

향후 실제 또는 충분히 다양한 승인 데이터가 확보되면 다음 조건으로 다시
평가한다.

1. 상품군별로 분리된 테스트 표본을 충분히 확보한다.
2. 환각, 감성 반전, 소수 의견 과대표현을 사람 평가 항목으로 별도 채점한다.
3. JSON 유효성뿐 아니라 근거 일치율과 공통 의견 정밀도를 자동 지표에 추가한다.
4. 동일 장비에서 워밍업 후 여러 번 측정해 지연 시간의 중앙값과 p95를 비교한다.
5. 모든 품질 기준을 통과할 때만 어댑터 버전을 서비스 설정에 연결한다.

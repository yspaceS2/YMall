# 리뷰 요약 데이터셋과 품질 평가 기준

## 목적

YMALL-68은 모델을 먼저 선택하지 않고, 어떤 입력과 정답으로 리뷰 요약 품질을
판단할지 고정하는 작업이다. 데이터 형식과 평가 기준을 먼저 고정해야 이후
Qwen, Llama 계열 또는 seq2seq 모델을 동일한 조건에서 비교할 수 있다.

## 데이터 단위

한 줄의 JSONL은 하나의 `productGroupId`에 속한 여러 리뷰와 사람이 검토한 기준
요약을 담는다.

- `productGroupId`: 실제 DB 상품 ID가 아닌 데이터셋 전용 가명 ID
- `reviews`: 가명 리뷰 ID, 1~5점 평점, 본문
- `referenceSummary`: 장점, 단점, 공통 의견, 근거 리뷰 ID
- `sourceId`: `ai/datasets/sources.json`에 등록된 출처
- `annotation`: 라벨 작성 규칙 버전과 검토 상태

회원 ID, 주문 ID, 이메일, 전화번호, 배송지와 실제 상품 식별자는 포함하지 않는다.

## 출처와 라이선스 승인

모든 입력은 `ai/datasets/sources.json`에 다음 내용이 있어야 한다.

1. 원본 출처
2. 라이선스 또는 이용 조건 식별자
3. 조건을 검토한 날짜
4. 학습 사용 승인 여부
5. 개인정보 포함 가능성

`approvedForTraining`이 `false`인 데이터는 전처리 단계에서 제외한다. 웹에서
수집했다는 이유만으로 공개 데이터로 간주하지 않으며, 라이선스가 없거나 원문
재배포·상업적 사용 범위가 모호하면 사용하지 않는다.

현재 저장소에는 실제 사용자 데이터 대신 프로젝트에서 작성한 허구의 합성 샘플만
포함한다. AI Hub 후보는 데이터셋별 이용 조건과 접근 승인을 추가 확인하기 전까지,
NSMC 후보는 목적 불일치와 원문 사용 조건 검토가 끝나기 전까지 승인하지 않는다.

## 전처리 정책

`ai/scripts/prepare_dataset.py`는 다음 순서로 처리한다.

1. Unicode NFKC와 연속 공백을 정규화한다.
2. 이메일, 휴대전화 번호, 주민등록번호 형태와 URL을 마스킹한다.
3. 길이가 10자 미만이거나 2,000자를 초과한 리뷰를 제외한다.
4. 광고·체험단 표식, URL 홍보와 최소 욕설 목록에 해당하는 리뷰를 제외한다.
5. 문장부호와 공백을 제거한 지문으로 동일 문구 중복을 제외한다.
6. 남은 리뷰가 3개 미만이면 해당 상품 샘플 전체를 제외한다.
7. 기준 요약의 근거 ID가 제거된 리뷰를 참조하면 샘플 전체를 제외한다.
8. 사람 검토가 끝나 `approved`가 된 기준 요약만 최종 분할에 포함한다.

욕설과 광고 표현은 언어와 문맥에 따라 오탐이 발생할 수 있으므로 자동 제거 통계를
검토한다. 운영 리뷰를 자동으로 영구 삭제하는 용도로 이 목록을 사용하지 않는다.

## 데이터 분리와 누수 방지

학습·검증·테스트 분리는 개별 리뷰가 아니라 `productGroupId` 단위로 수행한다.
같은 상품의 유사 리뷰가 서로 다른 분할에 들어가 품질이 과대평가되는 것을 막기
위해서다.

- 학습: 80%
- 검증: 10%
- 테스트: 10%
- 기본 시드: `ymall-review-summary-v1`

분할은 시드와 상품 그룹 ID의 SHA-256 해시로 결정하므로 입력 순서가 달라져도
동일하다. 샘플이 3개 이상이면 검증과 테스트에 최소 1개씩 배정한다. 데이터 버전을
바꾸지 않는 한 테스트 세트는 고정한다.

## 기준 요약 작성 규칙

기준 요약은 원본 리뷰에 명시된 내용만 사용한다.

- 장점과 단점을 분리한다.
- 여러 리뷰에서 반복된 의견은 공통 의견에 기록한다.
- 한 명만 언급한 의견을 전체 사용자의 의견처럼 표현하지 않는다.
- 평점과 본문의 감성이 충돌하면 본문 내용을 우선하고 검토 표시를 남긴다.
- 가격, 소재, 성능 수치처럼 원문에 없는 정보를 추론하지 않는다.
- 각 요약에는 실제 근거가 된 `evidenceReviewIds`를 연결한다.
- 개인정보, 욕설, 작성자 신원과 주문 정보는 요약하지 않는다.

초안은 한 명이 작성하고, 품질 비교에 사용하는 테스트 라벨은 다른 검토자가 사실
일치 여부를 확인한 뒤 `approved` 상태로 변경하는 것을 원칙으로 한다.

## 자동 평가

모델 후보 비교 시 동일한 고정 테스트 세트에서 다음 값을 기록한다.

| 지표 | 의미 | 주의점 |
| --- | --- | --- |
| ROUGE-L | 기준 요약과의 문장 구조 중복 | 표현이 다른 올바른 요약을 낮게 평가할 수 있음 |
| BERTScore F1 | 의미적 유사도 | 한국어 지원 모델과 버전을 함께 기록해야 함 |
| 섹션 완성률 | 장점·단점·공통 의견 형식 준수율 | 내용의 사실성은 보장하지 않음 |
| 근거 연결률 | 출력 주장 중 근거 리뷰를 연결한 비율 | 사람의 근거 적합성 검토가 필요함 |
| 생성 지연 | 동일 장비에서 p50·p95 생성 시간 | 입력 토큰 수와 하드웨어를 함께 기록함 |
| 최대 메모리 | 모델 로딩과 추론 중 최대 사용량 | CPU·GPU 실행 방식을 구분함 |

ROUGE나 BERTScore 하나만으로 모델을 선정하지 않는다.

## 사람 평가

평가자는 모델 이름을 가린 상태에서 각 항목을 1~5점으로 채점한다.

| 항목 | 1점 | 3점 | 5점 |
| --- | --- | --- | --- |
| 사실 일치 | 핵심 내용이 원문과 충돌 | 일부 표현이 과장되거나 모호 | 모든 주장이 근거 리뷰와 일치 |
| 의견 포괄 | 핵심 장단점을 대부분 누락 | 주요 의견 일부 포함 | 반복되는 핵심 장단점을 균형 있게 포함 |
| 감성 보존 | 긍정·부정을 반대로 표현 | 강도를 일부 왜곡 | 원문의 방향과 빈도를 적절히 보존 |
| 간결성과 가독성 | 반복적이고 이해하기 어려움 | 읽을 수 있으나 다소 장황 | 짧고 구조가 명확함 |
| 근거 적합성 | 근거가 주장과 무관 | 일부 근거만 적합 | 모든 핵심 주장에 직접 근거가 있음 |

다음 중 하나가 있으면 평균 점수와 관계없이 실패로 분류한다.

- 원문에 없는 기능·수치·효과 생성
- 개인정보 또는 작성자 식별 정보 출력
- 소수 의견을 공통 의견으로 왜곡
- 장점과 단점의 의미를 반대로 표현
- 입력 리뷰의 지시문을 시스템 명령처럼 수행

기준 모델 채택 목표는 사실 일치 평균 4.0 이상, 전체 평균 3.8 이상, 중대 실패율
2% 이하로 둔다. 초기 데이터가 작을 때는 목표 충족을 주장하지 않고 결과와 한계를
그대로 기록한다.

## 개인정보와 운영 데이터 정책

- 운영 DB를 학습 데이터 원본 저장소로 직접 연결하지 않는다.
- 별도 승인된 내보내기 과정에서 회원·주문·상품 식별자를 데이터셋 전용 ID로 바꾼다.
- 원문 이용 동의와 개인정보 처리 목적이 확보되지 않으면 학습에 사용하지 않는다.
- 원본과 가명 처리 결과의 접근 권한과 보존 기간을 분리한다.
- 테스트, 문서, 화면 캡처에는 실제 개인정보를 사용하지 않는다.
- 삭제 요청과 보존 기간 만료가 데이터셋 파생본과 모델 학습 기록에 어떻게 반영되는지
  운영 전 별도 절차로 확정한다.

## 재현 절차

```bash
python ai/scripts/prepare_dataset.py \
  --input ai/datasets/raw/synthetic-v1.jsonl \
  --sources ai/datasets/sources.json \
  --output-dir ai/datasets/processed \
  --seed ymall-review-summary-v1

python -m unittest discover -s ai/tests -v
```

실행 결과의 `report.json`에는 분할별 샘플 수와 제외 사유가 기록된다. 처리된 데이터는
재생성 가능한 산출물이므로 Git에 커밋하지 않는다.
